## 一、启动性能（检查要点 1）

| # | 位置 | 缺陷描述 | 大厂标准 | 级别 |
|---|---|---|---|---|
| 1.1 | `editor.html:470`、`preview.html:231`（`templates.js?v='+Date.now()`）、`templates.js:81`（每个模板 `?v=Date.now()`）、`editor.js:3313/3323`（导出链路同） | **`?v=Date.now()` 全量破缓存**：所有 JS 资源 URL 每次加载都带毫秒时间戳，浏览器/代理缓存完全失效——**首次与第 N 次加载完全等价**，每次打开页面都重新下载 ≈750KB。叠加服务端零缓存头（1.2），整个应用不存在任何一层缓存。时间戳破缓存掩盖的是"无版本管理"问题（交叉引用 §2.4 注释自述"绕过缓存"） | 内容寻址版本化：`?v=<构建指纹/内容hash>` 或版本号，配合 `Cache-Control: max-age=31536000, immutable`；模板清单变更才失效 | **P1** |
| 1.2 | `server.js:139-150`（`sendFile` 直接 `res.end(data)`） | **服务端静态服务零压缩**：无 Accept-Encoding 协商、无 gzip/br；~750KB 文本资源原样传输（理论可压至 ~150-180KB）；同时**零缓存头**（无 Cache-Control/ETag/Last-Modified），即使客户端去掉 `?v` 也无可缓存 | 静态资源启用 gzip/brotli（Node 内置 zlib 约 20 行）；显式 Cache-Control + ETag；或前置 Nginx/CDN 接管压缩与缓存 | **P1** |
| 1.3 | `editor.html:470 → templates.js:82 → 34 个模板 → editor.js` | **启动瀑布 = 37 个串行解析器阻塞请求**：document.write 逐个注入脚本，每请求一次 RTT、逐个下载解析执行；本机/内网无感，Docker 跨主机部署时 36 RTT 串行直接决定首屏时间——性能量化视角**交叉引用 §2.4/§2.5**（其已按可维护性记 P0，本条不重复计级） | 打包/合并（构建期 bundle）或 HTTP/2 + 预加载提示；加载失败 fail-fast | P2（交叉引用补强） |
| 1.4 | `server.js:141`（`fs.readFile` 每请求全量读入内存） | 静态文件无流式（`fs.createReadStream` + `pipe`）：每请求完整 buffer，并发下内存放大；当前单文件 ≤530KB 属可接受，标注技术债 | 大文件流式发送；本规模可接受 | P3 |

## 修复优先级建议（按收益/成本比）

1. **缓存与压缩体系（治 1.1/1.2/4.1，收益最大成本最小）**：`?v=Date.now()` 换固定版本指纹；server.js `sendFile` 加 zlib gzip 协商 + `Cache-Control`/ETag（约 30 行）。效果：首次传输 750KB→~170KB（**-77%**），二次加载接近 0 请求；导出链路同步受益。
2. **编辑器粒子同步预览页优化（治 2.1）**：transform + LUT + 元数据缓存的代码在 preview.html 已验证，回移 editor.js 即可消除 2625 写/帧；中期与报告方向 E 合并（单一粒子引擎，消灭双实现）。
3. **服务端异步化 + 代理加固（治 3.1/3.2）**：`fs.promises` + `keepAlive` Agent + 超时，各约 10 行。
4. **可见性感知与按需轮询（治 2.2/2.3）**：visibilitychange 挂起轮询/动画；无绑定 tag 跳过拉取。
5. **性能门禁（治 5.1）**：把性能调查报告 §6 的测量脚本化为 CI 基准，对"renderAll 耗时 / 动画节点数 / 资源总体积"设阈值，防回归。
