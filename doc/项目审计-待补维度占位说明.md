## 交付统一要求（所有维度必须遵守）

1. **只读审计**：不修改业务代码，仅产出审计文档。
2. **缺陷四要素**：每条缺陷必须包含 —— ① 文件 + 行号（可点击引用）② 缺陷描述 ③ 大厂/行业标准要求 ④ 严重级别。
3. **严重级别定义**（与已完成文档一致）：
   - **P0 严重**：数据丢失 / 崩溃 / 可利用安全漏洞 / 必然劣化
   - **P1 高**：高风险可维护性、健壮性、安全纵深缺陷
   - **P2 中**：规范类缺陷，可批量治理
   - **P3 低**：轻微瑕疵、风格问题
4. **结果落盘**：每个维度单独成文，放 `doc/` 目录，命名 `项目审计-<维度>缺陷清单.md`，并在本文档对应小节更新状态与文件链接。
5. **末尾要求**：每份清单末尾附「缺陷统计表」和「修复优先级建议」，格式参照已完成文档。

## 维度一：安全审计 ⬜（原计划已发起，结果丢失，需重做）

**范围**：`server.js`、`editor.js`、`editor.html`、`preview.html`、`embed-demo.html`、`Dockerfile`、`docker-compose.yml`、`.github/workflows/`

**检查要点**：

1. 路径穿越 / 文件名校验完备性（`/pfd-api/projects` 的文件名白名单是否有旁路）
2. XSS：innerHTML / `document.write` / SVG 字符串拼接 / URL 参数（`?d=`）/ 项目 JSON 反序列化后渲染的注入面（注意已完成审计发现 `esc()` 双实现且 editor 版转义不完备，见已完成文档 4.9，本维度需评估完整 XSS 利用链）
3. 反向代理 `/api/*` 的 SSRF、请求头注入、CORS 配置风险
4. 硬编码 IP / 敏感信息泄漏（已知 `http://192.168.1.78` 硬编码四处，需评估影响面）
5. 鉴权/权限控制缺失（项目库 API 任意读写删除）
6. DoS 防护（请求体大小、并发、超时、`readdirSync` 同步 IO 阻塞）
7. Docker 安全（基础镜像版本固定、非 root、最小能力）
8. CI/CD 供应链安全（Actions 版本是否固定 SHA、镜像 tag 策略）
9. `postMessage` origin 校验、iframe 嵌入安全
10. HTTP 安全响应头（CSP、X-Frame-Options 等）
