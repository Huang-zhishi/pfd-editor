## 0. 结论摘要

**发现 4 个 P0 级可利用漏洞，其中 2 个已用 PoC 实证可在一条未认证请求内触发：**

| PoC | 请求 | 实测结果 | 危害 |
|---|---|---|---|
| 任意文件读取 | `GET /%2e%2e%2fscada_layout_editor.html` | **200 / 13914 字节**，读到 web 根目录**之外**的文件 | 读取服务器任意可读文件（源码、配置、密钥、项目库） |
| 绕过 `/projects` 403 | `GET /../RS/projects/1%23.json` | **200 / 34820 字节**（同文件直连 `/projects/` 返回 403） | 项目库隔离形同虚设 |
| 远程 DoS | `GET /%` | `URIError: URI malformed` → **进程退出**，后续请求 `http=000` | 一条请求打死服务，可反复触发 |
| 无鉴权 | 任意 `GET/DELETE /pfd-api/projects/xxx.json` | 无需任何凭证即可列目录、读、写、删 | 全项目库任意读写删除 |

**根因集中在 `server.js` 静态文件服务与项目库接口两处**：`decodeURIComponent(req.url)` 的结果既没做异常保护，也没做"解析后路径必须落在 web 根内"的收敛校验。

## 1. 任意文件读取 / 路径穿越

| # | 位置 | 缺陷描述 | 大厂标准 | 级别 |
|---|---|---|---|---|
| 1.1 | `server.js` L206 `decodeURIComponent(req.url.split('?')[0])` + L231–247 `path.join(ROOT, urlPath)` → `sendFile()` | **路径穿越（任意文件读取）**：`urlPath` 直接来自 URL 且已先做 `decodeURIComponent`，随后 `path.join(ROOT, urlPath)` 会归一化 `..` 并**逃出 ROOT**，全程没有任何"结果必须位于 ROOT 之内"的校验 | OWASP A01 Broken Access Control / CWE-22；静态服务必须先 `path.resolve` 再用 `resolved.startsWith(ROOT + path.sep)` 收敛，越界一律 403 | **P0** |
| 1.2 | 同上，PoC | **实测**：`curl --path-as-is 'http://127.0.0.1:18092/%2e%2e%2fscada_layout_editor.html'` → `http=200 size=13914`，返回内容为项目根目录**同级目录**下的 HTML；`/%2e%2e%2fdigital_twin_system_spec.md` → `200 / 28978 字节` | 安全测试应覆盖编码变体（`%2e%2e%2f`、`..%2f`、双重编码） | **P0** |
| 1.3 | `server.js` L225–229（`/projects` 显式 403）vs L231+ 静态分支 | **防护可绕过**：`/projects/*` 被显式 403，但用 `/../RS/projects/x.json` 走静态分支即可读到同一文件（`reqPath` 不以 `/projects` 开头 → 绕过判断 → `path.join` 归一化后又指回 `ROOT/projects/x.json`）。**实测 `http=200 size=34820`** | 防护必须作用在**解析后的真实路径**上，而非原始 URL 字符串前缀 | **P0** |
| 1.4 | `server.js` L139–150 `sendFile()` | 404 响应体回显完整文件系统路径：`404 Not Found: D:\Java\GY\RS\projects\1`，泄漏服务器目录结构与部署位置 | 错误响应不得回显内部路径（信息泄漏），只回资源名与请求 ID | P2 |

## 2. 未捕获异常导致远程 DoS

| # | 位置 | 缺陷描述 | 大厂标准 | 级别 |
|---|---|---|---|---|
| 2.1 | `server.js` L205–206 `http.createServer((req,res)=>{ const reqPath = decodeURIComponent(...) })` | **畸形 URI 直接崩进程**：`decodeURIComponent` 对非法百分号编码抛 `URIError`，该调用位于请求处理器顶层、**无 try/catch**，Node 默认行为是打印堆栈并退出 | CWE-248 未捕获异常 / OWASP "fail safe"；所有来自请求的解析必须包裹并返回 400，且进程需有 `uncaughtException` 兜底与守护重启 | **P0** |
| 2.2 | 同上，PoC | **实测**：`curl --path-as-is 'http://127.0.0.1:18091/%'` → 进程退出，日志 `URIError: URI malformed at decodeURIComponent ... at Server.<anonymous> (server.js:206:19)`；随后同一实例 `/editor` 返回 `http=000`（连接被拒） | 崩溃必须可观测 + 自愈；关键路径应有存活探测 | **P0** |
| 2.3 | `server.js` L64–80 `readBody()` 超限分支 | 超限时 `reject()` + `req.destroy()`，调用方 catch 里再 `sendJSON(res,400)` 时 socket 已销毁，**客户端收到连接重置而非 413**，无法区分"太大"与"网络故障" | 超限应返回 413 + `Connection: close`，并保证响应先于连接关闭 | P3 |

## 4. 反向代理安全

| # | 位置 | 缺陷描述 | 大厂标准 | 级别 |
|---|---|---|---|---|
| 4.1 | `server.js` L154 `const targetUrl = API_TARGET + req.url`；L215 `req.url.startsWith('/api/')` | **`/api/` 前缀可被逃逸**：`new URL()` 会归一化 `..`，`/api/../editor` 最终请求后端 `/editor`，绕过后端任何基于前缀的访问控制。**实测**：`GET /api/../editor` 返回 404（后端自身的 `/editor` 路径响应），证明请求已离开 `/api` 前缀 | 代理应只放行白名单路径，且归一化后再次校验前缀 | P1 |
| 4.2 | `server.js` L176–178、L196–200 | **CORS 全开放**：代理响应与预检一律 `Access-Control-Allow-Origin: *` → 任意站点可借用户浏览器读取传感器数据，代理成为开放只读中继 | 明确 origin 白名单；凭据场景禁止 `*` | P1 |
| 4.3 | `server.js` L165–171 | **透传全部客户端请求头**（含 `cookie`、`authorization`、`x-forwarded-for`）：客户端凭据被转发给后端；`X-Forwarded-For` 可伪造，污染后端审计 | 请求头白名单（仅转发必要头），`X-Forwarded-*` 由代理侧重写 | P1 |
| 4.4 | `server.js` L173–192 | **无超时、无响应大小限制**：未设置 `proxyReq.setTimeout`/`server.timeout`，上游挂起即长期占用连接（慢速耗尽型 DoS）；`/api/*` 也无请求体大小限制 | 显式连接/读取超时 + 请求体上限 + 连接数限制 | P1 |
| 4.5 | `server.js` L175 `headers = {...proxyRes.headers}` | 原样回传上游全部响应头（含 `connection`/`transfer-encoding`），未做 hop-by-hop 头剥离 | 按 RFC 7230 剥离 hop-by-hop 头再回写 | P3 |

## 修复优先级建议

### 第一批（P0，建议 1 个工作日内闭环，均为小改动）

1. **收敛静态路径**（1.1–1.3）：`const resolved = path.resolve(ROOT, '.' + urlPath); if (!resolved.startsWith(ROOT + path.sep)) return 403;` —— 一行判断同时修掉 1.1/1.3，并让 `/projects` 的 403 真正生效。
2. **包住请求解析**（2.1）：`decodeURIComponent` 与整个请求处理器包 try/catch，异常返回 400；同时给进程加 `uncaughtException`/`unhandledRejection` 兜底（记录 + 优雅退出，由容器 `restart: unless-stopped` 拉起）。
3. **项目库接口加鉴权**（3.1）+ **默认只监听 127.0.0.1**（3.2）：读接口可先要求 `X-PFD-Token`（环境变量注入），写/删接口强制；`server.listen(PORT, HOST)` 的 `HOST` 默认 `127.0.0.1`，需要局域网访问时显式设置。

### 第二批（P1，建议本周内）

4. 代理层收口：路径白名单校验（4.1）、CORS 白名单（4.2）、请求头白名单（4.3）、超时与体积上限（4.4）。
5. 前端消息与数据入口：postMessage 双向 origin 校验（5.3/5.4）、`?doc=`/`?api=` 白名单与 schema 校验（5.5/5.6）、统一 `esc()`（5.1）。
6. 响应头基线（6.1/6.2）：`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、基础 CSP。
7. 镜像与编排（8.1/8.4）：digest 固定 + 端口绑 `127.0.0.1` + 资源上限。

### 第三批（P2/P3，随迭代治理）

8. Actions 固定 SHA + Dependabot（8.6）、结构化日志与审计（9.4）、配置外部化与 `.env.example`（7.1）、`.dockerignore` 白名单化（8.5）、容器健康检查与最小权限（8.2/8.3）。
9. 规范类问题（`innerHTML` 一致性、hop-by-hop 头、错误回显路径等）可由 lint 规则 + code review checklist 批量压制。

> 说明：本清单所有"实测"结论均来自本地独立实例（端口 18091–18093）复现，**未对 192.168.1.78 上的部署实例发起任何验证请求**。PoC 命令已在文中给出，便于修复后回归验证。

| 条目 | 修复内容 | 复测结果 |
|---|---|---|
| **4.1** `/api/` 前缀逃逸 | 代理前先拦含路径回溯的请求（字面量与编码形式都拦）；`new URL()` 归一化后再校验 `pathname` 仍在 `/api/` 内 | `/api/../editor`、`/api/%2e%2e/editor`、`/api/..%2fadmin` → **全部 400**；正常 `/api/sensors/values` → 200 |
