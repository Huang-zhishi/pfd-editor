**`preview.html` 的差异已定位为「一行」且属预期**：
```diff

- </body>
+ <script>window.__PFD_TOKEN="…";</script></body>
```

这是 `server.js` 的 **HTML 令牌注入功能**（安全审计 §3.1 配套）在服务时动态插入的，**不是版本不一致**。

> 经验：比对"服务器提供的 HTML"与"仓库源文件"时，必须预期令牌/白名单注入造成的差异，否则会误判为版本漂移。

**结论**：✅ **服务器运行的就是仓库已提交的版本，没有版本漂移**。（未包含 §2.2 的未提交改动，属预期。）

## 四、用户报的问题：「点击预览是空的项目」—— 已复现并定位

### 4.1 复现与定位

用无头浏览器做端到端测试（编辑器写存储 → 同源 iframe 打开预览页 → 统计渲染出的组件数）：

| 场景 | 预览页渲染结果 | 判定 |
|---|---|---|
| A. **编辑器为空白画布**（默认启动状态）→ 点预览 | **组件组 = 0**，标题"未命名流程" | ❌ **复现用户现象** |
| B. 载入演示工程 → 点预览 | 组件组 = 45 | ✅ 正常 |
| C. 从项目库载入（走 `applyProjectData`）→ 点预览 | 组件组 = 45，管道组 = 37 | ✅ 正常 |
| D. 浏览器里只有旧 key（`pfd_doc`）的历史数据 → 点预览 | 组件组 = 1，且旧 key 自动迁移为 `pfd_doc:v2` | ✅ 正常 |

### 4.2 根因

**编辑器现在默认启动为「空白画布」**（`editor.js` 初始化：*"启动为空白画布，由用户自行搭建"*），
而**预览页对空文档没有任何提示** —— 它只是把空画布如实渲染出来，用户看到的就是"空的项目"。

即：**不是预览功能坏了，而是"空文档"这个状态没有被表达出来**。链路本身完全正常（场景 B/C/D 都验证通过），存储键迁移也没问题（场景 D）。

### 4.3 建议修复（小改动，约 10 行）

在预览页（或编辑器的预览按钮）加**空状态提示**，二选一或都做：

1. **预览页**：渲染后若 `doc.components.length === 0`，在画布中央显示提示：
   > 「当前流程为空 · 请回到编辑器载入项目或拖入组件后再预览」
2. **编辑器侧**：点预览时若画布为空，先弹确认（或直接 `flash` 提示），避免打开一个必然空白的页面。

> ⚠️ **我没有直接改**：`preview.html` / `editor.js` 正是开发者 Agent 正在修改的文件（§2.2），
> 按协作约定我不碰他人未完成的工作。**建议由开发者 Agent 在其批次内一并处理**，或授权我改。
