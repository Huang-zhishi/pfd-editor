## 0. 实证结论摘要

**先说做得对的**（实测通过，避免误改）：

| 实测项 | 结果 |
|---|---|
| 保存 → 载入 → 再保存 二次往返等价（除 `savedAt`） | ✅ **true**（45 组件 / 37 管道数量与内容均一致） |
| 运行态字段（`_pts`/`_segs`）是否被剥离 | ✅ 保存后 pipe 字段只剩 `id/type/from/to/label/width/labelPos/bend/straight`，无 `_` 字段 |
| 反向重复连线去重 | ✅ 生效（a→b 与 b→a 只保留 1 条） |
| 监控项位号与后端目录一致性 | ✅ **13/13 全部命中** |
| 布线遇到退化输入（端点重合、同向端口、自环）是否崩溃 | ✅ 均未抛异常，返回有效点列 |

**核心问题集中在三处**：

1. **保存时会静默删掉任何以 `_` 开头的用户字段**（实测 `props._private`/`props._note` 被丢弃）—— 这是"按命名约定隔离持久层与运行层"的必然代价（架构清单 §10.2 已记结构缺陷，**本条补充实证证据与业务影响**）。
2. **导入路径与载入路径校验不一致**：`btnImport` 直接 `JSON.parse` 后赋给 `doc`，缺 `pipes` 字段即渲染崩溃（实测抛 `Cannot read properties of undefined (reading 'length')`）；而本地文件载入路径有 normalize，同样数据正常。
3. **位号与后端目录大面积失配**：硬编码 `KNOWN_TAGS` **25 个全部不在**后端目录中（100% 失效）；演示工程 27 个传感器位号有 **5 个不在**目录中（含一处明显的错别字），这些参数将**永久显示 `--` 且无任何提示**。

## 1. 数据往返一致性

| # | 位置 | 缺陷描述 | 大厂标准 | 级别 |
|---|---|---|---|---|
| 1.1 | `editor.js` L2771 `stripRuntimeFields(v){ return JSON.parse(v, (k,val)=> k.charAt(0)==='_' ? undefined : val) }` | **静默删除任意 `_` 前缀字段（含用户数据）**：reviver 作用于**每一层**的所有 key，实测输入 `props:{name:'测试', _private:'用户数据', _note:'备注'}` → 输出 `props:{"name":"测试"}`，两个字段无声消失。命名约定充当了持久层边界（交叉引用 §10.2） | 持久模型与运行模型必须显式分离（外挂 Map / 序列化白名单），不得用"字段名前缀"隐式约定；任何丢弃行为需可观测 | **P1** |
| 1.2 | `editor.js` L2774 `buildProjectData()` | 保存产物同时写**顶层 `title`** 与 **`meta.title`**（双写）：实测两者一致（`1#流程2.0`），但顶层 `title` 在载入侧不被读取（L2793 只取 `data.meta`）→ 外部工具改顶层 `title` 会被静默忽略 | 单一数据源，禁止同一语义两处存储 | P3 |
| 1.3 | `editor.js` L2654 `btnImport`：`doc=JSON.parse(txt)` 后直接 `renderAll()` | **导入路径无任何校验/迁移/normalize**：实测缺 `pipes` 字段的项目文件 → 渲染抛 `Cannot read properties of undefined (reading 'length')`，页面处于半渲染状态且无有效提示 | 入口统一 `parse → validate → migrate → normalize` 管道（交叉引用 §10.5/§10.6） | **P1** |
| 1.4 | `editor.js` L2654（导入） vs L2791–2793（载入 normalize） | **两条入口行为不一致**：同一份"缺 pipes/meta"的数据，导入路径崩溃、载入路径正常。用户无法预期哪种方式可靠 | 多入口必须收敛到同一个 loader；差异只允许体现在"数据来源"而非"校验强度" | **P1** |
| 1.5 | 全仓无 schema 校验/版本识别代码 | 载入时只做字段兜底（`data.components \|\| []`），**不校验字段类型、不识别 `version`、不做迁移链**；错误类型（如 `components` 是对象而非数组）会以难以定位的报错在深层爆开 | 入口 schema validate（JSON Schema/Zod 等价物）+ 版本识别 + 明确拒绝信息 | **P1** |
| 1.6 | `editor.js` L2611–2612 `undo/redo` 的 `JSON.parse(histStack[...])` | 历史串损坏即抛异常、撤销整体失效（交叉引用 §5.2）；**本维度补充**：历史快照走 `JSON.stringify(doc)`，而保存走 `stripRuntimeFields`，两者对 `_` 字段的处理**不一致** → 撤销后 `_pts` 恢复、保存后消失，运行态与持久态的边界随操作路径漂移 | 序列化单一入口（`serializeDoc`），undo 与 save 共用 | P2 |
| 1.7 | `preview.html` L670–676 `?doc=` / L676 localStorage / postMessage 三路载入 | 预览端**独立实现**一套 normalize（与编辑器不同名同义），同一份 JSON 在两页解析结果可能不同（交叉引用 §10.6/§4.6） | 共享 `loadDoc(source)` 管道 | P2 |
| 1.8 | `editor.js` L2927 / L2939 | 从本地文件载入后 `_currentProjectFile = null`（与项目库解除关联），此时点"保存"会转去打开项目面板而非直接落盘 —— 行为正确但**用户无感知**（无"当前未关联项目库"的状态提示） | 状态可见化：界面明示当前文档来源与保存目标 | P3 |

## 3. 连接拓扑约束

| # | 位置 | 缺陷描述 | 大厂标准 | 级别 |
|---|---|---|---|---|
| 3.1 | `editor.js` L1654 `addPipe()` / L1676 `sameConnection()`（实测） | **自环可创建**：`from` 与 `to` 为同一组件同一端口时，`sameConnection` 不命中（比较的是"两个端点对"，自环两端相同），管道被正常创建（实测管道数 1）→ 产生零长度/退化几何的连线 | 连线前校验 `from.cid!==to.cid` 或至少端口不同；自环应拒绝并提示 | P2 |

| 3.4 | `editor.js` L376 渲染分支 + 实测 E4/E5 | **悬空管道与错误端口被静默跳过**：`from` 指向不存在的组件、或端口名不存在时，渲染不报错（`_pts` 为空），管道**静默不可见**；但该管道仍在 `doc.pipes` 中并被保存 → 损坏数据长期潜伏，用户只看到"线少了" | 载入/渲染时做拓扑完整性检查，汇总报告"N 条管道因端口缺失无法渲染" | P2 |

## 修复优先级建议

### 第一批（P1，直接影响业务正确性，建议优先）

1. **位号失效治理（4.1–4.3）** —— 这是本维度**最影响实际使用**的一类问题：
   - 废弃 `KNOWN_TAGS` 硬编码回退，离线时改为显式提示"未连接后端，无法校验位号"；
   - 保存/载入时批量校验 `params[].k`/`runTags[].tag`/`monitorTags[].tag`，对不在目录中的位号汇总告警（可直接复用现有 `sensorCatalog`）；
   - 修正演示工程中 5 个失效位号（`1#窑体供气风机C0204阀位` → `1#窑体供热气风机C0204阀位` 等），并在文档中明确位号变更流程。
2. **统一载入入口（1.3–1.5）**：`btnImport` 改为走与本地载入相同的 normalize + 校验；补 `version` 识别与字段类型校验；损坏文件给出明确拒绝信息而不是深层 TypeError。
3. **持久层与运行层显式分离（1.1）**：用序列化白名单或外挂运行态 Map 替代 `_` 前缀约定；至少把"被丢弃的字段"记入日志/控制台，避免静默。
4. **并发与未保存保护（5.2/5.4）**：服务端 POST 增加 mtime/ETag 前置校验（冲突返回 409）；编辑器加 `beforeunload` 与内部切换确认。

### 第二批（P2，健壮性与体验）

5. 几何与拓扑（2.1/2.2/3.1/3.2/3.4）：几何入口 `Number.isFinite` 防御 + 跳过并告警；拒绝同端口自环；端口连接数在属性面板可见；载入时输出"N 条管道因端口缺失无法渲染"的汇总提示。
6. 跨页与多标签（5.1/5.3/1.7）：加 `storage`/`BroadcastChannel` 同步或最后写入告警；预览端与编辑器共用 normalize；localStorage 通道加版本戳。
7. 数据源治理（4.4）：推动后端在入库侧 trim 位号并加唯一约束。

### 第三批（P3）
