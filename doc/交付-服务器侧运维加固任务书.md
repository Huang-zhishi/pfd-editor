## 0. ⚠️ 最高优先级：不做这两件事，服务会直接不可用

本次代码升级（`v1.0.0`）**收紧了两个部署默认值**。如果你的服务器是 systemd 部署且**没有显式设置**这两个环境变量，升级后会出现「服务起来了但外部连不上 / 实时数据全空」：

| 变量 | 旧行为 | 新行为 | 你必须做的 |
|---|---|---|---|
| `HOST` | 未设置时绑 `0.0.0.0`（局域网可达） | 未设置时绑 **`127.0.0.1`**（仅本机） | **显式设置 `HOST=0.0.0.0`**，否则外部访问不了 |
| `API_TARGET` | 未设置时默认 `http://192.168.1.78` | **无默认值**，未配置时 `/api/*` 返回 **503** | **显式设置 `API_TARGET`**，否则传感器数据全空 |

**症状对照**（便于快速判断是不是这个原因）：
- 外部浏览器打不开页面 → 十有八九是 `HOST` 没设
- 页面能开但传感器/实时值一直空、状态栏显示「后端: 离线」 → 是 `API_TARGET` 没设（浏览器控制台会看到 `/api/...` 返回 503，body 是 `{"success":false,"error":"服务端未配置后端地址..."}`）

> 若你希望**保持只允许本机/反向代理访问**（更安全），则不要设 `HOST`，但需确认调用方走 `127.0.0.1` 或经 nginx 反代。

## 1. 任务清单

### T1 · 应用部署必改项（P0，先做）

**现状**：服务器 systemd 单元可能只有 `Environment=PORT=8090`（甚至没有 `API_TARGET`）。

**要做**：按下方配置补环境变量，然后 `daemon-reload` + `restart`。

```bash
# 用 drop-in 方式覆盖，不动原始单元文件（推荐，便于回滚）
sudo mkdir -p /etc/systemd/system/pfd-editor.service.d
sudo tee /etc/systemd/system/pfd-editor.service.d/10-deploy.conf >/dev/null <<'EOF'
[Service]
Environment=PORT=8090
# —— 本次升级必改 ——
Environment=HOST=0.0.0.0
Environment=API_TARGET=http://127.0.0.1:8080
# 项目库接口令牌（强烈建议启用；生成方式：openssl rand -hex 24）
Environment=PFD_API_TOKEN=REPLACE_WITH_RANDOM_TOKEN
# —— 按需的跨域白名单（默认全部关闭，留空即不开放）——
# Environment=PFD_CORS_ORIGINS=https://ops.example
# Environment=PFD_EMBED_ORIGINS=https://portal.example
# Environment=PFD_API_ALLOW=
EOF

sudo systemctl daemon-reload
sudo systemctl restart pfd-editor
```

**⚠️ 关于 `API_TARGET` 的取值**：旧代码默认是 `http://192.168.1.78`（即后端在另一台机器的 80 端口）。
如果后端其实跑在**本机**，请按实际监听端口填（例如 `http://127.0.0.1:8080`）；
**不要照抄 `192.168.1.78`**，除非后端确实在那台机器的 80 端口。**这一条请务必与现场确认。**

**验收**：
```bash
systemctl is-active pfd-editor                  # 期望 active
curl -s localhost:8090/healthz                  # 期望 {"ok":true,...}
curl -s localhost:8090/readyz                   # 期望 {"ok":true,"projects":true}
curl -s -o /dev/null -w '%{http_code}\n' "localhost:8090/api/sensors/values?limit=1"
```
关于最后一条的判读（**不要误判**）：
- **200** → 代理与后端都正常
- **503** → `API_TARGET` 没配置（本次升级的必改项）→ 回到 §0 处理
- **502** → 配置**正确**，但后端不可达（后端服务没起 / 地址或端口不对）→ 去查后端，不是本服务的配置问题

再从**另一台机器**访问 `http://<服务器IP>:8090/editor`，确认外部可达（打不开就是 `HOST` 没设 `0.0.0.0`）。

### T2 · systemd 加固 + 重启风暴限制（对应 §10.7 / §7.6）

**现状**：`deploy.sh` 生成的单元只有 `Restart=on-failure` / `RestartSec=3`，无任何安全加固，也无重启次数限制 —— 若进程持续崩溃（例如被畸形请求打到旧版本的那个已修复的崩溃点），会无限重启且无人知晓。

**要做**：

```bash
sudo tee /etc/systemd/system/pfd-editor.service.d/20-hardening.conf >/dev/null <<'EOF'
# ⚠️ 重启风暴限制必须写在 [Unit] 段 —— systemd ≥230 起 StartLimit* 已从 [Service]
#    迁到 [Unit]，写错段位只会被静默忽略（不报错但完全不生效）。
[Unit]
StartLimitIntervalSec=60
StartLimitBurst=5

[Service]
# 运行用户（若尚未创建：sudo adduser --system --group --home /opt/pfd-editor pfd）
User=pfd
Group=pfd

# —— 最小权限加固 ——
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
PrivateDevices=true
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictSUIDSGID=true
RestrictRealtime=true
RestrictNamespaces=true
LockPersonality=true

# 只放开项目库目录可写（ProtectSystem=strict 会把其余路径挂成只读）
ReadWritePaths=/opt/pfd-editor/projects

# —— 重启策略 ——
Restart=on-failure
RestartSec=3

# —— 资源上限 ——
MemoryMax=256M
CPUQuota=50%

# —— 日志走 journald ——
StandardOutput=journal
StandardError=journal
SyslogIdentifier=pfd-editor
EOF

sudo systemctl daemon-reload && sudo systemctl restart pfd-editor
```

> **❗ 两个容易踩的坑，已为你排除**：
> 1. **不要加 `MemoryDenyWriteExecute=true`** —— Node 的 V8 需要可写可执行内存（JIT），加上会让进程**启动即失败**。
> 2. **`StartLimit*` 不要写在 `[Service]`** —— systemd ≥230 起它属于 `[Unit]`，写错段位会被静默忽略（上面已放在 `[Unit]`）。

**⚠️ 注意 `User=pfd` 与目录属主**：`ProtectSystem=strict` + `ReadWritePaths` 要求 `/opt/pfd-editor/projects` 对 `pfd` 可写：
```bash
sudo chown -R pfd:pfd /opt/pfd-editor/projects
```

**验收**：
```bash
systemctl show pfd-editor -p User -p NoNewPrivileges -p ProtectSystem -p StartLimitBurst -p MemoryMax
systemd-analyze security pfd-editor        # 看加固评分（越低越好，加固前通常在 9.x）
# 验证项目库可写（令牌若已启用需带 header）
curl -s -X POST localhost:8090/pfd-api/projects/_probe.json \
  -H 'Content-Type: application/json' -H "X-PFD-Token: $PFD_API_TOKEN" \
  -d '{"version":1,"components":[],"pipes":[],"meta":{}}'
curl -s -X DELETE localhost:8090/pfd-api/projects/_probe.json -H "X-PFD-Token: $PFD_API_TOKEN"
```

### T3 · 日志留存与轮转（对应 §9.x / §7.1）

**现状**：服务日志走 systemd 默认 journald（无大小/保留期上限）；Windows 侧 `start.cmd` 把日志写到仓库根目录且**每次启动清空**（`del`），故障重启后现场丢失。

**要做（服务器侧，只做 journald 部分）**：

```bash
sudo mkdir -p /etc/systemd/journald.conf.d
sudo tee /etc/systemd/journald.conf.d/pfd.conf >/dev/null <<'EOF'
[Journal]
# 全系统日志上限与保留期（按磁盘容量调整）
SystemMaxUse=500M
SystemMaxFileSize=50M
MaxRetentionSec=1month
# 本项目日志单独标识，便于检索：journalctl -t pfd-editor
EOF
sudo systemctl restart systemd-journald
```

**验收**：
```bash
journalctl -t pfd-editor -n 20 --no-pager      # 能看到结构化 JSON 行（含 "event":"audit"）
journalctl -t pfd-editor | grep '"event":"audit"' | tail -5   # 审计留痕可查
```

> 说明：服务端已改为**单行 JSON 结构化日志**（`{"ts","level","event",...}`），写删操作有独立审计记录（含来源 IP、UA、字节数）。你在做日志采集/告警时可直接按 `event` 字段分流。

### T4 · 部署后验证与冒烟（对应 §9.2）

**要做**：每次部署后跑一遍，**全部通过才算部署成功**（不要只看 `systemctl is-active`）。

```bash
set -e
B=http://127.0.0.1:8090
TOKEN="${PFD_API_TOKEN:-}"          # 未启用令牌则留空
H=(); [ -n "$TOKEN" ] && H=(-H "X-PFD-Token: $TOKEN")

echo "== 健康 =="
curl -fsS "$B/healthz" | grep -q '"ok":true'
curl -fsS "$B/readyz"  | grep -q '"ok":true'

echo "== 页面 =="
for p in /editor /preview /embed-demo.html; do
  code=$(curl -s -o /dev/null -w '%{http_code}' "$B$p"); echo "  $p -> $code"; [ "$code" = 200 ]
done

echo "== 项目库（令牌未启用时会 401，属预期）=="
code=$(curl -s -o /dev/null -w '%{http_code}' "$B/pfd-api/projects"); echo "  /pfd-api/projects -> $code"

echo "== 后端代理 =="
code=$(curl -s -o /dev/null -w '%{http_code}' "$B/api/sensors/values?limit=1"); echo "  /api/... -> $code"; [ "$code" = 200 ]

echo "== 安全基线（越界路径必须被拒）=="
for evil in "/%2e%2e%2fpackage.json" "/../README.md"; do
  code=$(curl -s --path-as-is -o /dev/null -w '%{http_code}' "$B$evil"); echo "  $evil -> $code"; [ "$code" = 403 ]
done

echo "== 安全响应头 =="
curl -s -D - -o /dev/null "$B/editor" | grep -qi 'x-content-type-options: nosniff'
echo "ALL PASS"
```

## 2. 不要做的事（边界）

| 不要 | 原因 |
|---|---|
| 不要改仓库源码（`server.js` / `editor.js` / `preview.html` 等） | 仓库侧有多个 Agent 在并行改，容易冲突；发现问题请写到协作文件消息区 |

| 不要删 `/opt/pfd-editor/projects` | 那是业务数据（项目库） |
